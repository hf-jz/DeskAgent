
# 习惯工程 · 总体设计方案 v1

日期：2026-07-24 ｜ 状态：已实现（v1.2，2026-07-26；修复与增强明细见 docs/审查报告-v1.md）

## 1. 为什么叫"习惯工程"

DeskApp 今天的能力是"响应"：用户开口，planner 规划，worker 执行。这是工具。
工具的瓶颈不在执行能力，而在**上下文**——每次对话都是从零开始，agent 不知道你今天做了什么、正在做什么、接下来大概率要做什么。

而用户每天的使用过程本身就是最丰富的上下文源：

- 9:00 打开 TradingAgents 看隔夜分析（已有 cron 产出的 IntelHub 情报）
- 上午 VSCode + Chrome + Terminal 三件套 → 在 Cerebro 项目深度工作
- 下午浏览 arXiv / 公众号资料 → 在做调研
- 傍晚打开 streamlit:8501 复盘

这些**重复出现的行为模式就是习惯**。习惯工程的定义：

> 通过持续观察使用者的数字行为，提炼结构化的习惯模型，并把习惯转化为 agent 的上下文、记忆与自动化能力，使 DeskApp 从"被动响应"进化为"主动协作"。

它是"伙伴"定位的技术载体：宠物之所以是伙伴而不是图标，是因为它**记得你**。

## 2. 核心概念模型：五层金字塔

---
```
        ┌─────────────┐
        │ 5 例程/自动化 │  习惯 → 可执行能力（一键例程、cron、skill）
        ├─────────────┤
        │ 4 习惯卡片    │  结构化模式：触发条件 × 行为序列 × 置信度
        ├─────────────┤
        │ 3 摘要       │  每日/每周 LLM 压缩：今天做了什么、什么是重复的
        ├─────────────┤
        │ 2 活动时间线  │  按时间排列的会话段（app/url/标题 × 时长）
        ├─────────────┤
        │ 1 原始事件    │  前台窗口采样、URL、文件事件（30 天滚动删除）
        └─────────────┘
```
---

设计要点：**每一层都是对下一层的有损压缩，每一层都可以被用户检视和纠正。** 原始数据短命，认知产物长存。这既控制存储，也控制隐私暴露面——长期保留的是"9 点看行情"这样的模式，而不是"9:03:27 你打开了某个 URL"。

### 习惯卡片（核心数据结构）

一张习惯卡是习惯工程的原子单位：

---
```json
{
  "id": "habit_morning_market",
  "name": "晨间看行情",
  "kind": "time_routine",            // time_routine | sequence | context | preference
  "trigger": { "time_range": "08:30-10:00", "days": ["mon","tue","wed","thu","fri"] },
  "pattern": {
    "apps": ["Google Chrome"],
    "urls": ["localhost:8501", "eastmoney.com"],
    "sequence": ["打开 TradingAgents", "浏览隔夜情报", "查看持仓"]
  },
  "confidence": 0.86,
  "evidence_count": 23,
  "first_seen": "2026-07-01",
  "last_seen": "2026-07-24",
  "status": "confirmed",             // candidate → confirmed → active → stale → archived
  "user_note": "开盘前必看"
}
```
---

### 习惯生命周期

---
```
candidate（系统发现，置信度低）
   │  用户确认 / 证据累积超阈值
   ▼
confirmed（用户背书过的）
   │  绑定了主动动作（简报项、例程）
   ▼
active（在服务中）
   │  N 天未出现
   ▼
stale → archived
```
---

**置信度 = 频次 × 时间规律性（触发时刻分布的熵的倒数）× 新近度衰减。** 用户在环确认是置信度的最强信号：宠物问一次"我注意到你每天开盘前都看 TradingAgents，这是你的晨间例程吗？"，用户一句"是"顶过二十次观察。

## 3. 感知层（Collector）——看什么，怎么看

按隐私敏感度分三级，**默认只开 Tier 1**：

| 级别 | 数据源 | 说明 | 默认 |
|---|---|---|---|
| Tier 1 | 前台应用 + 窗口标题 | macOS AppleScript/`active-win`，5s 采样 + 去抖合并 | 开 |
| Tier 1 | 浏览器 URL | Chrome/Safari/Arc/Edge 的 AppleScript「当前标签页 URL」 | 开 |
| Tier 1 | DeskApp 自身会话 | hermes session DB——用户跟 agent 说了什么，是最直接的习惯金矿 | 开 |
| Tier 2 | 文件系统活动 | chokidar 监听项目目录的读写（聚焦，不全盘监听） | 关，可选 |
| Tier 2 | 日历 | macOS Calendar 只读，用于对齐"计划 vs 实际" | 关，可选 |
| Tier 3 | 定时截图 + 本地 VLM 摘要 | "深度感知"，能理解屏幕内容但侵入性强 | 关，显式 opt-in |
| 永不 | 键盘记录、剪贴板、密码域、隐身窗口 | 不碰 | — |

隐私护栏：

- **黑名单**：1Password、银行/支付类站点、检测到隐身窗口时自动跳过。
- **暂停观察**：托盘菜单一键暂停；宠物头顶显示观察状态点（绿=观察中，灰=暂停）。
- **应用白名单**：用户可限定只观察指定应用集合。
- **记忆透明**：所有采集内容在 HabitPanel 可检索、可删除（按天/按源/全部）。

技术选型：主进程内嵌 Node 采集器。前台窗口用 `active-win`（macOS 原生二进制，Electron 生态成熟，需辅助功能权限）；浏览器 URL 用 AppleScript；均无需额外原生开发。

## 4. 记忆层（Store）

本地 SQLite（`better-sqlite3`），落在 `~/Library/Application Support/deskapp/habit.db`，**不出本机**。

---
```
events     (id, ts, kind, app, title, url, duration)     -- 原始事件，30 天滚动删除
segments   (id, start_ts, end_ts, app, url, title)       -- 去抖合并后的活动段，90 天
summaries  (id, date, period, text, habit_refs)          -- 每日/每周摘要，永久
habits     (id, name, kind, trigger_json, pattern_json,
            confidence, evidence_count, status,
            first_seen, last_seen, user_note)            -- 习惯卡，直至归档
suggestions(id, habit_id, kind, payload, status, created) -- 主动建议的提出与采纳记录
```
---

保留策略即隐私策略：层越低越短命。**原始事件 30 天自动清除，用户随时可一键清空。**

## 5. 认知层（Engine）——从事件到习惯

### 双时间尺度学习

- **每日摘要（当晚 23:00 或次日首次启动）**：当天 segments → worker 模型（deepseek-v4-pro，便宜）压缩成一段自然语言摘要 + 结构化活动标签。成本极低（一次调用）。
- **每周固化（周日晚）**：7 天摘要 → planner 模型（kimi-k3）做跨天模式识别，产出习惯卡的新建/强化/弱化提案。

### 习惯提取的两条路径

1. **算法路径（免费，实时）**：对 events 做统计聚类——同时段重复 app/url 组合 → time_routine 候选；固定先后序列 → sequence 候选；项目目录活动与 app 组合 → context 候选。产出 candidate 卡。
2. **LLM 路径（每周，有成本）**：摘要做语义级归纳，能发现算法看不出的模式（"每周五下午你会整理本周资料"）。

两条路径的产出统一进 `habits` 表，candidate 状态的卡等待用户确认或证据累积。

### 关键闭环：习惯写回 hermes

这是本方案与"又一个屏幕时间统计工具"的本质区别——**习惯的终点是 agent 的能力**：

- preference 类习惯 → 写入 hermes user-profile 记忆（如"用户开盘前必看 TradingAgents"），之后每一轮对话天然携带；
- sequence 类习惯且用户确认 → 提议生成为 hermes skill 或 cron 任务（见 §7 影子自动化）；
- 所有 confirmed 习惯 → 对话启动时按相关性注入 bridge 的上下文（复用现有 injectContext 机制）。

观察 → 学习 → 记住 → 行动，四环闭合。DeskApp 是眼睛，hermes 是大脑，planner/worker 是手。

## 6. 行动层（Proactive）——懂你有什么用

1. **晨间简报**：首次点亮屏幕时，宠物气泡主动问候："早。IntelHub 9 点情报已就绪；昨天你在 Cerebro 上深度工作了 4.5 小时；今天周五，按习惯你下午会整理周报。需要我打开 TradingAgents 吗？"
2. **例程一键执行**：confirmed 的 time_routine 可绑定成"例程"——一句话或一键，agent 依次打开该例程的全部 app/页面/资料。
3. **偏离提醒（关怀式，不说教）**："今天 11 点了还没看行情，平时这个点已经看过了——要我帮你拉一下吗？" 每周最多 N 次，可整体关闭。
4. **上下文预载**：检测到 9:25 打开 Chrome → 预先把隔夜情报摘要取好，用户开口即答。
5. **习惯注入对话**：与当前话题相关的习惯卡自动进入上下文，agent 的回答因此"知道你是谁"。

## 7. 惊喜设计（超出提示的部分）

### 7.1 影子自动化（Shadow Automation）
系统统计到某个**手动重复工作流**出现 ≥5 次（例如：每天收盘后导出数据 → 打开 Excel → 截图发群），宠物主动提议："这个流程你做了 5 次了，要我把它变成一键技能吗？" 用户确认后，由 planner 生成 hermes skill 或 cron 任务。**DeskApp 观察你干活，然后把你的活变成它自己的技能**——这是习惯工程的复利。

### 7.2 懂你指数（宠物亲密度）
习惯卡覆盖率、确认数、连续相伴天数汇成一个"懂你指数"，宠物外观/动作随之成长解锁。桌面宠物品类独有的情感化设计：了解你不是功能，是养成。

### 7.3 节奏画像（Rhythm Profile）
不止知道"你做什么"，还知道"你怎么做"：深度工作块时长分布、上下文切换频率（碎片指数）、一天的高效时段。用于：在你进入深度工作块时自动静音非紧急通知；周报里呈现节奏变化趋势。

### 7.4 飞行记录仪（Day Replay）
时间线可回放：一天的活动压缩成可拖动的彩色时间轴（按项目/应用着色），点击任意段看当时的窗口标题与资料。复盘、找"我上周看的那个网页"变得轻而易举。

### 7.5 周报
每周日生成一份精美 HTML 周报（复用项目里已有的报告模板能力）：时间分布、项目投入、习惯演化、新发现的习惯、影子自动化提案。习惯工程的成果因此**可见**。

### 7.6 习惯即接口
每张 confirmed 习惯卡同时是一个可被对话调用的能力："进入工作状态"= 打开 Cerebro 项目三件套；"晨间例程"= 行情 + 情报 + 日历。习惯从"被记录的数据"变成"可召唤的动作"。

## 8. 与现有架构的集成

| 现有模块 | 集成方式 |
|---|---|
| `src/main/` 模块化服务 | 新增 `habit-service.ts`（采集调度）、`habit-store.ts`（SQLite） |
| `src/shared/ipc-channels.ts` | 按现有契约模式新增 `habit:*` 通道（invoke/push 双向类型安全） |
| `bridge.py` / hermes | 摘要与固化任务走现有 bridge；worker 模型做每日摘要控成本，planner 做每周固化 |
| hermes memory / skills | preference 习惯写回 user 记忆；sequence 习惯经确认后生成 skill/cron |
| hermes cron | 每日 23:00 摘要、周日固化用现有 cron 体系承载（与 IntelHub 同一模式：采集→编译→产出） |
| 渲染层 | 新增 `HabitPanel`（类比 TaskTreePanel 的窗口模式）+ 宠物气泡的习惯发现提示 + 设置页"观察与隐私"Tab |
| 托盘 | "暂停观察"开关 + 观察状态指示 |

依赖新增：`better-sqlite3`、`active-win`（均为成熟包，主进程专用）。

## 9. 分期路线图

**Phase 0 — 地基（1 天）**
habit 目录、SQLite schema、`habit-service.ts` 骨架、前台窗口采样器跑通落库。
验收：跑一小时，`events`/`segments` 表有正确数据；辅助功能权限引导完成。

**Phase 1 — 时间线 + 每日摘要（1-2 天）**
浏览器 URL 采集、每日 23:00 worker 摘要流水线、HabitPanel v1（只读时间线）。
验收：连续 3 天有摘要；时间线与真实使用吻合。

**Phase 2 — 习惯卡 + 人在环确认（2-3 天）**
统计算法提 candidate、气泡确认交互、习惯卡网格 UI、观察与隐私 Tab（黑名单/暂停/删除）。
验收：产生 ≥3 张 candidate 卡；确认/否决流转正确；隐私开关即时生效。

**Phase 3 — 主动服务（2-3 天）**
晨间简报、偏离提醒、习惯注入对话上下文、懂你指数 v1。
验收：简报内容与昨日真实活动一致；注入后 agent 回答可见 habit 感知。

**Phase 4 — 影子自动化 + 周报（3-4 天）**
工作流重复检测、skill/cron 生成提案流、HTML 周报、飞行记录仪。
验收：一次真实的"观察→提议→生成 skill→执行"全链路；周报渲染无溢出。

**Phase 5 — 打磨**
节奏画像驱动的通知管理、亲密度外观成长、性能与电量优化（采样自适应降频）。

原则：每个 Phase 结束都是可用状态，不搞大爆炸式开发。

## 10. 隐私与安全原则（一等公民）

1. **本地优先**：一切数据存本机，无任何遥测上传；LLM 摘要只发送摘要所需的聚合文本，不发送原始事件流。
2. **最小采集**：默认 Tier 1；Tier 2/3 逐项显式开启。
3. **可审计**：HabitPanel 里每一条记录可见、可删；设置里一键清空全部习惯数据。
4. **用户主权**：习惯的确认、否决、归档完全由用户决定；系统只提议，不擅自自动化。
5. **敏感规避**：黑名单 + 隐身检测 + 密码域永不触碰。

## 11. 开放问题（需你拍板）

1. **采集范围默认集**：Tier 1（窗口标题 + 浏览器 URL + DeskApp 会话）作为默认是否同意？文件活动（Tier 2）是否一开始就纳入？
2. **观察时段**：全天候，还是限定（如 8:00–24:00）？是否需要"周末不观察"类规则？
3. **摘要用模型**：每日摘要走 worker（省成本）是否符合预期，还是摘要质量优先走 planner？
4. **懂你指数**：是否接受游戏化/养成方向？还是希望保持纯工具向、弱情感化？
5. **影子自动化的边界**：自动生成的 skill/cron 是否一律需人工确认后才激活？（建议：一律确认）
6. **命名与位置**：代码模块放 `src/main/habit/` 而文档与数据 schema 放 `habit/`，还是全部实现代码也独立放 `habit/` 再以路径别名引入？（建议前者，符合现有 main 进程结构）

## 12. 实现状态快照（v1.2，2026-07-26）

> 本方案 Phase 0–4 主体已落地为 `src/main/habit/`（11 个模块）。细节以代码与 docs/审查报告-v1.md 为准。

- **感知层**：5s 前台窗口采样、浏览器 URL（30s）、黑名单（含中文敏感词 + 命中回溯清除）、锁屏/无窗口不桥接。
- **记忆层**：SQLite `habit.db`（events/segments/summaries/habits/suggestions 五表），标题/URL 经 `safeStorage` 加密，事件 30 天、段 90 天滚动清理。
- **认知层**：每日 23:00 管道（摘要→提取→维护，启动补齐昨日）；摘要双模式（默认本地统计，opt-in LLM 走 worker 模型，负载脱敏）。
- **行动层**：晨间简报、偏离提醒（4h 冷却 + 日上限 3）、习惯注入对话上下文（双向实体匹配）、例程一键执行（`open -a` 白名单）、影子自动化提案。
- **懂你指数**：0-100 确定性公式（观察天数/确认活跃卡/平均置信度/摘要积累）+ LLM 一句话解读（每日缓存，本地规则兜底）。
- **周报**：周日管道自动生成；LLM 叙事 + 本地数据附录，失败降级纯本地统计；面板可手动触发。
- **隐私**：知情同意门（未授权不采集）、暂停/AI 摘要持久化、一键导出/彻底删除。
- **未做**：Phase 4 的 HTML 周报渲染与飞行记录仪、Phase 5 全部（节奏画像通知、亲密度外观、采样自适应）。
